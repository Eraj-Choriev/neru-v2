Механизм: `scripts/build-config.mjs` при сборке (`buildCommand` в
`vercel.json`) или локально берёт переменные из окружения либо `.env` и
генерирует `js/config.js`. И `.env`, и `config.js` в `.gitignore`, `.env*` — в
`.vercelignore`. Без ключа или с ключом недопустимого формата скрипт выходит с
кодом 1. Деплой тогда падает, и Vercel продолжает отдавать предыдущую версию.

**Ограничение, о котором важно знать.** Браузерный ключ карты по определению
виден в браузере: он уходит в каждом запросе тайлов. `.env` убирает ключ из
репозитория, но не из Network-вкладки. Реальная защита — ограничение по
Referer в 2GIS Platform Manager.

**Нужно сделать вручную (у меня нет прав на эти действия):**

1. **Vercel → neru-v2 → Settings → Environment Variables:** добавить
   `NUR_2GIS_KEY` и `NUR_CF_BEACON_TOKEN` для Production *и* Preview. Пока их
   нет, сборка падает. Сайт при этом не ломается: остаётся текущий деплой.
2. **Перевыпустить ключ 2GIS.** Старый остаётся в истории git (коммит `8cdc973`)
   навсегда. Удаление из текущих файлов историю не чистит.
3. **В 2GIS Platform Manager** ограничить новый ключ доменами
   `neru-v2.vercel.app` (+ превью-домены, если нужны карты в превью).

Дополнительно: скрипт `@2gis/mapgl-clusterer@2.5.2` с unpkg теперь
подключён с SRI-хэшем. Подменённый на CDN файл браузер откажется выполнять.

## 4. Найдено, но не исправлено (по приоритету)

1. **139 вызовов `backdrop-filter` в CSS.** Самое дорогое для GPU слабых
   Android-телефонов: каждый блюр — отдельный проход по пикселям под элементом
   при любом изменении под ним (а под ним всегда WebGL-карта). Стоит проверить
   на реальном бюджетном устройстве (Chrome DevTools → Rendering → Frame
   rendering stats). При просадках — `@media (max-resolution: …)` или флаг
   «облегчённый режим» с непрозрачными подложками.
2. **CSS — 7 300 строк со следами старой тёмной темы.** Блок
   `:root[data-theme="light"]` встречается 254 раза. Приложение теперь только
   светлое, поэтому тёмные значения и переопределения — мёртвый вес, который
   браузер всё равно парсит. Чистка безопасна, но требует визуальной регрессии
   (скриншоты до/после), поэтому вынесена в отдельную задачу.
3. **Старт ждёт фид станций.** Лоадер скрывается только после
   `await loadStations()`. При медленном API это до 12 с белого экрана, хотя
   карта уже готова. Можно скрывать лоадер сразу после инициализации карты и
   показывать скелетон-статистику.
4. **Нет Content-Security-Policy.** Остальные заголовки безопасности в
   `vercel.json` хорошие. CSP с allow-list (`2gis.com`, `unpkg.com`,
   `fonts.googleapis.com`, `parking.dc.tj`, `allorigins.win`,
   `project-osrm.org`, `cloudflareinsights.com`) закрыл бы XSS-класс атак.
   Требует теста в браузере, потому что 2GIS SDK использует воркеры и blob.
5. **Публичные бесплатные сервисы как зависимость:** `allorigins.win` (CORS-прокси)
   и `router.project-osrm.org` (маршруты) без SLA. Свой маленький прокси на
   Vercel Functions убрал бы обе точки отказа. Заодно данные пользователей
   (координаты в запросах маршрутов) перестали бы уходить третьим лицам.
6. **Таймер парковки** раз в секунду переписывает `textContent` у ~6
   элементов, даже когда текст не изменился. Нагрузка небольшая, но
   бессмысленная: сравнивать перед записью.
7. **`analysis.html` (64 КБ) деплоится публично.** Это внутренний
   маркетинговый документ («больше возвратов» и т. п.). Если он не для
   пользователей, его стоит исключить через `.vercelignore`.
