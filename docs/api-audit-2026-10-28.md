# API audit — 2026-10-28

Direct GET requests to both public endpoints succeeded. Both responses were
passed through the current application normalizers using Node's VM.

## Parking

- Endpoint: https://api.parking.dc.tj/api/v1/getMarkerParking
- 243 raw records; 227 valid zones, matching the counts documented in the
  existing module and the September 21 browser review.
- Valid zones report 3,881 total spaces, including 199 accessible spaces.
  These are capacity figures, not live availability.
- 16 records still lack usable geometry and are correctly excluded:
  93, 124, 136, 138, 145, 146, 129, 130, 131, 162, 189, 238, 270, 132, 184, 185.
- All returned fields are already consumed by `normalizeZone`; no occupancy,
  free-space count, or other additional metric is present. Every tariff is 3.
- Equal totals do not establish that individual IDs or attributes are unchanged:
  no earlier full snapshot was available for a record-by-record comparison.

## Charging

- Endpoint: https://api.parking.dc.tj/api/v1/getMarkerPower
- 341 records; all 341 normalize successfully, with 682 connectors.
- At capture: 416 Available, 263 Charging, 3 Start charging.
- The September 21 review recorded 376 stations; today's total is lower by 35.
  This alone does not establish which stations were added or removed.
- All three connector states are supported. Top-level `status_connector_1/2`
  conflict with `connectors_info` in some records, so they should not override
  the detailed connector statuses used by the application.

No runtime changes are required to accept the current feeds. Stations are
loaded dynamically; parking zones are loaded dynamically with a 24-hour cache.
The accompanying JSON stores parking records, charging IDs, and field names
as a baseline for future comparisons, without freezing live charging status.
