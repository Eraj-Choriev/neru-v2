# NŪR Native — стек и архитектура

Черновик от 2026-08-13. Разработка ещё не начата, скоуп v1 не закрыт.

Приложение: суперприложение для таксистов Душанбе. Три слоя точек на одной
карте — электрозарядки, АЗС, рестораны — плюс парковки из текущего веба.

---

## 1. Ядро

| Слой | Выбор | Почему |
|---|---|---|
| Рантайм | **Expo**, managed + dev-client | Всё нужное — first-party. EAS Build снимает локальную возню с Xcode и Android Studio |
| Язык | **TypeScript**, strict | Нормализация станций сейчас нетипизирована и это уже кусалось; три источника данных вместо одного сделают хуже |
| Навигация | **expo-router** | Файловый роутинг, глубокие ссылки из коробки — понадобятся для «открыть точку по ссылке» |
| Состояние | **Zustand** | Заменяет шину `CustomEvent` (6 событий) |
| Серверные данные | **TanStack Query** | Три источника с разными интервалами обновления, ретраями и кэшем. Руками это писать не надо |
| Хранилище | **AsyncStorage** | Замена localStorage: язык, аналитика, сессия парковки |
| Анимации | **Reanimated 3** + **Gesture Handler** | Только на переходы и жесты, без стеклянных эффектов |
| Списки | **FlashList** | Списки точек будут длинными, `FlatList` на 300+ элементах заметно хуже |

Версии не фиксируем — ставить через `expo install`, он подбирает совместимые
с версией SDK.

## 2. Карта — главное решение

Вы просите Apple Maps. Прямо: **Apple Maps не существует на Android.** Это
не ограничение библиотеки, MapKit — часть iOS. Кроссплатформенно это всегда
означает разные карты на разных платформах.

Рабочий вариант:

```
react-native-maps, PROVIDER_DEFAULT
  iOS     → Apple Maps (MapKit)
  Android → Google Maps
```

Один API в коде, нативная карта на каждой платформе. Пользователь на iPhone
видит привычные Apple Maps, на Android — привычный Google.

### Что это меняет по сравнению с прошлым решением

Раньше я советовал MapLibre + тёмные тайлы CARTO. **Эта причина исчезла:** вы
убрали тёмную тему, а именно ради неё нужен был контроль над стилем тайлов.
Нативные карты теперь строго лучше — они бесплатны на iOS, привычны
пользователю и не тратят трафик на свои тайлы.

### Практические следствия

| | iOS | Android |
|---|---|---|
| Ключ API | не нужен | **нужен** — Maps SDK for Android, в Google Cloud Console |
| Кастомный стиль | нет (только светлый/тёмный) | есть, JSON-стиль |
| Стоимость | 0 | бесплатный тир, дальше по прайсу |

Из этого следует, что **карты будут визуально разными на двух платформах**, и
это нормально — так работает большинство нативных приложений. Единый бренд
держим на своих слоях: маркеры, карточки, панели, а не на подложке.

### Альтернатива, за которой стоит следить

`expo-maps` — first-party модуль Expo, оборачивает MapKit на iOS и Google Maps
на Android. Идеологически чище, но моложе и беднее по API, чем
`react-native-maps`. Стартуем на `react-native-maps`; если `expo-maps` к моменту
работы над картой закроет наши потребности — переезд дешёвый, слой карты у нас
будет за своим интерфейсом.

### Кластеризация

370 электрозарядок + АЗС + рестораны = легко за тысячу маркеров. Нативные
маркеры при таком количестве тормозят на обеих платформах.

**`supercluster`** — считаем кластеры в JS, рисуем то, что реально попало в
видимую область. Готовые обёртки вроде `react-native-map-clustering` не берём:
они прячут контроль над тем, что именно рендерится, а это ровно тот рычаг,
который нам понадобится.

## 3. Источники данных — самый большой пробел

| Слой | Источник | Статус |
|---|---|---|
| Электрозарядки | `api.parking.dc.tj/api/v1/getMarkerPower` | **Есть**, работает |
| Парковки | `api.parking.dc.tj/api/v1/getMarkerParking` | **Есть**, работает |
| АЗС | — | **Источника нет** |
| Рестораны | — | **Источника нет** |

Две трети нового функционала не имеют данных. Это не про код — пока источник
не выбран, эти экраны нечем наполнять.

### Кандидаты

| Источник | Покрытие Душанбе | Цена | Замечание |
|---|---|---|---|
| **OpenStreetMap** (`amenity=fuel`, `amenity=restaurant`) | переменное, надо мерить | бесплатно | Публичный Overpass **не годится как рантайм-API** — лимиты и без SLA. Правильно: выгрузить регион, положить к себе, обновлять по расписанию |
| **2GIS** | сильное в Центральной Азии, Душанбе входит в покрытие | по договору | Вероятно лучший вариант по качеству данных для этого города |
| **Google Places** | среднее вне крупных сетей | дорого за запрос | Платим за каждый запрос, данные по Душанбе слабее, чем по Европе |
| **Yandex** | заметное в регионе | по договору | Разумный запасной вариант |

**Рекомендация: сначала померить, потом выбирать.** Выгрузить Душанбе из OSM,
посчитать, сколько там АЗС и ресторанов с адресом и часами работы, и сравнить с
2GIS. Это день работы, и он определяет архитектуру всего слоя данных.

### Отсюда следует новый компонент, которого сейчас нет

Сегодня приложение — чистый клиент, без бэкенда. Как только появляются АЗС и
рестораны из OSM или по коммерческому ключу, нужен **свой сервис**: он держит
выгрузку, обновляет её, прячет ключи (в мобильном приложении ключ не секрет — его
достают из бандла за минуту) и отдаёт всё одним нормализованным ответом.

Минимально: одна функция + object storage + крон на обновление.

## 4. Сервисы и нативные возможности

| Задача | Пакет | Зачем |
|---|---|---|
| Геолокация | `expo-location` | Позиция водителя, слежение при активном маршруте |
| Уведомления | `expo-notifications` | Счётчик парковки в фоне — то, чего веб не умел в принципе |
| Открыть внешнюю навигацию | `expo-linking` | Deep link в Яндекс.Навигатор / 2GIS / Google Maps |
| Звонок в заведение | `expo-linking` (`tel:`) | Позвонить в ресторан из карточки |
| Хаптика | `expo-haptics` | Замена `navigator.vibrate`, работает на iOS (в вебе не работала) |
| Иконки | `@expo/vector-icons` | SF Symbols на iOS не переносимы на Android |
| Шрифты | `expo-font` | Manrope / Bricolage переезжают из веба |
| Сбои | **Sentry** | Свои устройства кончились — нужны стектрейсы с чужих |
| Аналитика продукта | PostHog / Amplitude | По желанию, позже |
| Обновления | **EAS Update** | Правки JS без прохода через сторы |

### Турн-бай-турн навигацию внутрь не тащим

Таксист уже сидит в Яндекс.Навигаторе или 2GIS. Своя навигация — это отдельный
продукт на полгода, и он проиграет. Наша задача: **найти точку и отдать её во
внешний навигатор одним нажатием**.

Маршрут внутри приложения оставляем только как оценку — «сколько ехать», линия на
карте, как сейчас в вебе.

### Про OSRM — предупреждение

Веб сейчас ходит в `router.project-osrm.org`. Это **демо-сервер проекта, он
явно не предназначен для продакшена** — без SLA, с лимитами, и живой трафик
таксистов с него срежут. К релизу нужно либо поднять свой OSRM (он открытый,
Таджикистан — маленький регион, влезет на скромный сервер), либо взять платный
роутинг. Своё дешевле.

## 5. Оформление

Стекло не делаем. Обычный таб-бар, обычный топ-бар, сплошные фоны.

- **Только светлая тема.** Одно замечание и иду дальше: цвета всё равно
  описываем семантическими токенами (`surface`, `textPrimary`, `accent`), а не
  хардкодим hex по компонентам. Тёмную тему тогда можно будет добавить правкой
  одного файла, а не всего приложения. Стоит это ноль лишней работы сейчас.
- Таб-бар — стандартный из `expo-router`, нативный вид на каждой платформе.
- Палитра, типографика и скругления переезжают из веба.
- Анимации — только переходы экранов и отклик на нажатие.

### Требования из-за того, что за рулём

Это не обычное приложение — им пользуются в движении. Отсюда:

- **Крупные цели нажатия**, заметно больше минимальных 44pt.
- **Читаемость на солнце** — светлая тема здесь как раз в плюс, но нужен
  реальный контраст, а не серый по белому.
- **Одна рука.** Всё важное — в нижней половине экрана.
- **Живёт без сети.** Последний известный список точек кэшируем на диск и
  показываем со штампом времени. Водитель в мёртвой зоне должен видеть данные,
  а не спиннер.
- **Батарея.** Слежение за позицией включаем только при активном маршруте и
  глушим, когда приложение ушло в фон без маршрута.

## 6. Что переезжает из веба

| Переносится почти как есть | Пишется заново |
|---|---|
| `i18n.js` — 975 строк, 3 языка | `map.js` — 870 строк на Leaflet |
| `finder.js` — чистая математика | `ui.js` — 881 строка DOM |
| `geolocation.js` — гаверсинус | `css/style.css` — 6849 строк |
| `router.js` — запрос к OSRM | Рендер аналитики и парковки |
| `api.js` — нормализация станций | `sw.js` + `pwa.js` — удаляются |

**Отдельно приятное:** в `api.js` умирает цепочка CORS-прокси
(`corsproxy.io`, `allorigins.win`). У нативного `fetch` нет CORS — запрос идёт
прямо, без чужого посредника и без таймаута в 8 секунд на каждую попытку.

Общий код (`api`, `finder`, `geolocation`, `router`, `i18n`) уходит в общий
пакет монорепо. Хвост этого решения: **веб сейчас без сборки**, плоские
`<script>`-теги. Чтобы импортировать общий пакет, ему придётся обзавестись
сборщиком — отдельная задача, её надо запланировать.

## 7. Открытые вопросы

1. **Источник по АЗС и ресторанам.** Блокирует две трети нового функционала.
   Первый шаг — замерить покрытие Душанбе в OSM и сравнить с 2GIS.
2. **Скоуп v1.** Всё сразу или сначала зарядки с картой?
3. **Бэкенд.** Кто его пишет и на чём.
4. **Продакшен-роутинг.** Свой OSRM или платный сервис.
5. **Аккаунты разработчика.** Apple Developer — 99 $/год, Google Play — 25 $
   единоразово. Оформление занимает время, лучше начать заранее.
6. **Нужны ли пользователи.** Избранное, история поездок, синхронизация между
   устройствами — всё это требует аккаунтов и меняет архитектуру.
