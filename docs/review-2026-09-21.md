# Техническое и продуктовое ревью NŪR

Дата: 21 сентября 2026. Объект: работающая веб/PWA-версия, не будущие макеты React Native.

## Вывод

Рабочая основа для поиска зарядок и парковочных зон есть: модули разделены, данные нормализуются, предусмотрены локализация, геолокация и маршруты. Однако приложение пока нельзя представлять как систему бронирования, оплаты или гарантированного фонового мониторинга. Этих серверных интеграций нет.

Проверены исходники API, парковок, маршрутов, геолокации, контроллера, UI, уведомлений, аналитики, service worker и конфигурация размещения. Проведён браузерный smoke-test; это не нагрузочный тест и не проверка на физических iPhone/Android. Реальные SMS, платежи и закрытое приложение не тестировались: соответствующих интеграций нет.

## Что остаётся сделать технически

### P1 — достоверность информации

- **Открытая карточка не получает свежие статусы:** app.loadStations откладывает перерисовку при has-popup. Обновлять содержимое конкретной открытой карточки без закрытия, сохраняя прокрутку и фокус.
- **Старые данные визуально похожи на актуальные:** timestamp сохранён, но нужен постоянный статус «Обновлено … / нет связи / данные устарели» и кнопка повторить. После ошибки нельзя обещать доступность разъёма.
- **Парковочный расчёт на границах расписания:** freeMode фиксируется при старте. Сессия, начатая ночью, останется бесплатной после открытия, а дневная может продолжать считаться после закрытия. Не менять формулу по догадке: нужны согласованные правила оператора о пересечении платных интервалов, льготных минутах и округлении. До интеграции сумма — оценка, таймер — личное напоминание, а не официальная парковочная сессия.
- **ETA зарядки не предсказывает освобождение:** модель предполагает батарею 50 кВт·ч и заряд до 90%, не знает ограничение машины, разделение мощности и момент отъезда. Показывать «оценка зарядки», не обещание свободного места.
- **Парковки не имеют live occupancy:** общее количество мест нельзя подписывать «свободно». Макеты с «14 из 40 свободно» пока не обеспечены API.
- **«Лучший выбор» сейчас не доказан:** рабочий поиск сортирует по прямому расстоянию. Назвать результат «Ближайшие», затем отдельно разработать ранжирование по доступности, часам работы, совместимости и дороге.

### P1 — инфраструктура

- Убрать зависимость от публичного AllOrigins: собственный endpoint с фиксированным upstream, таймаутом, проверкой схемы, коротким кешем и ограничением частоты. Не делать открытый proxy с произвольным URL.
- Выбрать поставщика карт и маршрутов с подходящим договором перед масштабированием. OSM Standard — временная подложка без SLA; массовая предзагрузка и скачивание города запрещены. HTTP-кеш браузера сохранён, SW тайлы не перехватывает.
- Закрытое приложение не опрашивает станции: текущие уведомления — не полноценная серверная push-система. Нужен сервер, который наблюдает изменения и отправляет Web Push подписчикам.
- Продолжить тесты на разрыв сети, подвисшее тело ответа, corrupted localStorage, 429, GPS permission revocation, восстановление PWA и смену часового пояса.

### P2 — поддерживаемость

- Перевести глобальные singleton-модули постепенно на ES modules; затем выделить чистое ядро нормализации/геометрии/тарифов для React Native. Не требуется сразу переписывать весь UI.
- Около 7 тысяч строк CSS содержат несколько поздних слоёв переопределений. Свести навбар, карточки и темы к отдельным компонентным блокам после визуальных эталонов.
- localStorage не везде защищён от исключений; централизовать чтение, запись, версию и валидацию данных. Кеш парковок проверяет массив, но не схему каждой зоны.
- Добавить единый lifecycle модалок: trap focus, возврат фокуса инициатору, Escape и недоступность фоновых контролов. aria-modal само этого не делает.
- CDN-зависимости закреплены по версиям, но приложение зависит от внешних CDN и шрифтов. Для стабильного офлайна хранить необходимые ресурсы самостоятельно с учётом лицензий.
- analysis.html содержит устаревшие утверждения об отсутствии PWA/уведомлений. Это отдельная презентационная страница, а не достоверный аудит текущего кода.
- Полный security-аудит не выполнен. В основных карточках есть HTML-экранирование; это положительно, но не заменяет проверку всех внешних данных и CSP.

## Дизайн и интерфейс

Оценка: рабочий интерфейс с избыточной декоративностью и недостаточно явными состояниями данных.

1. **Главный экран:** карта, поиск, два понятных режима «Зарядки / Парковки», геолокация. Языки, тему, уведомления и установку перенести в настройки/контекстные подсказки. Сейчас верхняя строка занята настройками вместо поиска.
2. **Навигация:** «Карта / Рядом / Избранное / Настройки». Кнопка «Найти» сейчас действие, аналитика — второстепенная панель; их не следует выдавать за равнозначные разделы. Переключение режима зарядок/парковок разместить над картой.
3. **Карточка зарядки:** название → свободные/всего → подтверждённый тип разъёма → мощность → тариф → маршрут. Для отсутствующих данных писать «Не указано». Разъём №1 из API не означает CCS2 — тип нельзя дорисовывать по номеру.
4. **Карточка парковки:** зона, адрес/границы, часы, тариф, способы оплаты оператора, личный таймер. Явно отделить вместимость от текущей занятости.
5. **Список:** убрать повторяющиеся мини-логотипы, крупные ранги и светящиеся поверхности; оставить спокойные карточки с одним главным действием. «Пешком» вторично для водителя; время в пути показывать только при реальном расчёте маршрута.
6. **Кластеры карты:** уменьшить тени/ореол. Число и нейтральная заливка важнее объёмного пузыря. Цвет кластера не должен обещать, что все точки внутри свободны.
7. **Доступность:** сохранять текстовые подписи; обеспечить фокус и минимум 44px для управляющих кнопок, проверить увеличение текста на 200%, контраст и reduced motion на устройстве. Полного замера всех контрастов в этом проходе не было.
8. **Состояния:** проектировать loading, empty, offline/stale, denied GPS, route failed, unknown connector, paid hours ended. Они важнее дополнительных баннеров.
9. **Единый стиль:** для будущей нативной версии сохранять ранее выбранные светлую тему, нейтральные поверхности и отсутствие стекла. Не переносить автоматически весь визуальный язык текущего веба.

Основание: apple-design → Accessibility, Layout, Color, Typography, Icons. Общий принцип: предсказуемая навигация, читаемая иерархия, понятные действия и статус не только цветом.

## Функции и интеграции: порядок внедрения

| Этап | Что | Зависимости |
|---|---|---|
| 1 | Поиск по имени/адресу, избранное, недавно открытые точки | Текущий API и локальное хранение; вход не нужен |
| 1 | Фильтры «Свободна», «Открыта», мощность; отметка свежести | Текущий API, корректный парсер часов, обработка ошибок |
| 1 | Поделиться точкой, внешняя навигация | Web Share с fallback, проверенные deep links |
| 2 | Профиль авто и фильтр совместимости | Реальные типы разъёмов от оператора; нельзя вывести из мощности |
| 2 | Сообщение «Не работает», фото въезда | Бэкенд, модерация, хранение файлов, защита от спама |
| 2 | SMS-вход для синхронизации избранного | SMS-провайдер с доставкой +992, серверная OTP-проверка, TTL, лимиты попыток и повторов, сессии |
| 2 | Уведомление об освобождении выбранной станции | Серверный мониторинг + Web Push; не только setInterval клиента |
| 3 | Оплата/бронирование/официальная история парковки | Договор и API оператора, подтверждение транзакций, idempotency и webhooks |
| Позже | АЗС, еда, мойки | Проверенные источники данных; не мешать запуску двух основных сценариев |

Предлагаемая следующая архитектура: статический клиент → небольшой собственный API → адаптеры операторов. PostgreSQL для аккаунтов/избранного/сообщений; PostGIS понадобится при реальном серверном геопоиске, а не ради 376 точек. Серверный кеш использовать по необходимости; Redis не обязателен на старте. Логи ошибок должны исключать номера телефонов, координаты и OTP.

Для нативного приложения оставить React Native + Expo + TypeScript с общим доменным ядром. Apple Maps в вебе требует MapKit JS token; это отдельная интеграция, а не настройка Leaflet. В нативной версии выбрать карты для iOS/Android по покрытию Душанбе и условиям поставщика. Не добавлять SMS-барьер перед обычным просмотром карты без продуктовой причины.

## Проверки и ограничения

- `node --test tests/regression.cjs`: 9 успешных регрессионных тестов.
- `node --check` всех js/*.js и sw.js; `git diff --check` — успешно.
- Browser smoke: 376 зарядных станций, 227 валидных парковочных зон, инициализация проходит.
- Размеры 390×844 и 1440×900: горизонтального overflow не обнаружено.
- После замены карт и отключения локального beacon: в проверенном запуске 0 ошибок консоли.
- Визуально проверены мобильная карта и список. Прочие панели оценены прежде всего по коду; это не полный ручной QA каждого состояния.
- Не проверены физические GPS, фоновые уведомления, реальная сеть оператора и поведение реального iOS PWA. Деплой не выполнялся.
