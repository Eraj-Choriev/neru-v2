# Как гнать Stitch, чтобы не получить AI-трэш

> **Обновлено после подключения Stitch MCP.** У MCP есть `upload_design_md` —
> `DESIGN.md` грузится в проект целиком и превращается в дизайн-систему, которая
> дальше применяется к каждому экрану автоматически. **Это отменяет ручную
> преамбулу из шага 1** — она нужна только при работе через веб-интерфейс без
> MCP. Шаги 2–6 (порядок экранов, точечные правки, реальный контент, приёмка)
> остаются в силе полностью.
>
> Рабочий проект: `3879649954381605228`, дизайн-система:
> `8c834cdca48047f1ba5281ef3ea00fa4`.

Инструкция к `DESIGN.md`. При работе **без** MCP сам `DESIGN.md` целиком не
вставляется — идёт сжатая преамбула ниже.

---

## Почему нельзя вставить весь файл

Stitch генерирует по одному экрану и держит короткое внимание. На 300 строках
правил он теряет середину: возьмёт цвета, забудет запреты, вернёт Material с
фиолетовой кнопкой. Работает обратное — **короткий плотный блок, повторяемый
перед каждым экраном.**

И главное: Stitch генерирует каждый экран независимо, поэтому экраны
**расходятся между собой**. Пять красивых экранов из разных приложений — это и
есть тот самый AI-трэш. Лечится порядком работы, а не текстом промпта.

---

## Шаг 0. Настройки до первого промпта

- Режим **App**, не Web
- Модель — **самая сильная из доступных, не Flash**. Flash экономит на
  соблюдении ограничений, а у нас ограничений много
- Иконка палитры в поле ввода — если там задаются цвета темы, **забейте их
  один раз руками** вместо описания словами. Заданный цвет соблюдается лучше,
  чем описанный. (Проверить не смог — за логином.)

---

## Шаг 1. Преамбула — копировать перед КАЖДЫМ экраном

```
STYLE — apply to every screen, no exceptions.

Native mobile app screen, light theme only.
Monochrome interface. Background #FAFAF9, surfaces #FFFFFF, primary text
#1C1C1A, secondary text #6B6B66, hairline borders #E7E5E1.
Primary button: solid #1C1C1A slab, white text, 56px tall, 14px radius, flat.
Colour appears ONLY on map pins and small status dots — never on buttons,
bars, headers or backgrounds. Charging #2F5DAF, fuel #B87608, food #A64B3C,
parking #5A6675.
Typeface Manrope. All numbers, distances, prices and times in JetBrains Mono.
Lists are 72px rows separated by 1px hairline dividers — never a stack of
cards. Cards, where used, have a 1px border and no shadow.
Minimum touch target 56px. Minimum body text 15pt. 8pt spacing grid.
Content is in Russian, using real Dushanbe street names.

BANNED: glassmorphism, frosted blur, translucency, dark mode, gradients,
glows, coloured shadows, emojis, Inter, Roboto, Material purple, floating
capsule tab bars, decorative colour, lorem ipsum, placeholder names.
```

Дальше — промпт экрана из `DESIGN.md` §8.

---

## Шаг 2. Первым делать НЕ карту

Начните со **списка «Рядом»** (§8, экран 2).

Причина: список показывает всю систему сразу — типографику, ритм отступов,
разделители, точки статуса, моноширинные цифры — и при этом предсказуем. Карта
же генерируется хуже всего: модель рисует *картинку* карты, и вы будете
править фальшивую графику вместо интерфейса.

Список доводится до готовности и становится **эталоном**. Все остальные экраны
делаются после него и сверяются с ним.

---

## Шаг 3. Итерации — по одной правке за промпт

Не переписывайте промпт целиком. Stitch умеет доправлять сгенерированный экран,
и точечная команда исполняется точнее, чем новая простыня.

Хорошо:

```
Make the row height 72px and remove the card containers — use 1px hairline
dividers between rows instead.
```

```
Move the distance to the right edge and set it in monospace. Keep everything
else unchanged.
```

Плохо: «сделай покрасивее», «более премиально», «добавь современности». От таких
формулировок модель добавляет градиент и тень — ровно то, что мы запретили.

**Правило: если правку нельзя выразить числом или конкретным существительным,
она сформулирована плохо.**

---

## Шаг 4. Реальный контент с первого промпта

Самый громкий признак AI-трэша — не цвета, а **текст**. «Lorem ipsum»,
«John Doe», «Station Name» убивают ощущение продукта мгновенно.

Задавайте настоящее сразу: улицы Рудаки, Сомони, Айни; названия на русском;
правдоподобные цифры — «1.4 км», «22 кВт», «3 сом./час», а не «99%» и «50+».

И сразу же кириллицу. Русские строки на 20–40% длиннее английских: макет,
собранный на слове «Charging», разваливается на «Зарядные станции». Узнать это
на первом экране дешевле, чем на пятом.

---

## Шаг 5. Приёмка — по чеклисту, а не «нравится / не нравится»

Прогоняйте каждый сгенерированный экран по списку. Любое «нет» — правка, а не
компромисс.

- [ ] Цвет есть только на пинах и точках статуса. Кнопки, бары, шапки — серые
- [ ] Основная кнопка одна на экран
- [ ] Нет теней, кроме как под реально плавающими элементами
- [ ] Нет градиентов, свечения, стекла, блюра
- [ ] Список — строки с разделителями, а не стопка карточек
- [ ] Цифры моноширинные
- [ ] Ничего мельче 15pt
- [ ] Все цели нажатия от 56px
- [ ] Текст настоящий, на русском, без плейсхолдеров
- [ ] Нет эмодзи
- [ ] Отступы кратны 8
- [ ] Экран отвечает на один вопрос, а не на три

---

## Шаг 6. Согласованность между экранами

После эталонного списка каждый следующий промпт начинайте так:

```
Match the visual system of the previous screen exactly: same typography scale,
same 20px screen margins, same hairline dividers, same monochrome interface
with colour only on status dots.
```

Когда все экраны готовы — **пересмотрите их подряд, один за другим**. Расхождения
видны только в сравнении: разная высота шапки, разный отступ, разная толщина
шрифта в заголовке. Это и есть та работа, которая отличает набор картинок от
дизайна.

---

## Чего от Stitch ждать не надо

Он выдаёт раскладку и иерархию. Не выдаёт:

- **Работающую карту** — нарисует картинку. Настоящая будет
  `react-native-maps` со своими контролами, которые в макет не попадут
- **Правильную кириллицу** — вернёт латиницу, даже если просить русский
- **Мобильные размеры целей** — тянет к веб-масштабу, 56px придётся требовать
- **Дисциплину по цвету** — любит подкрашивать кнопки, вычищать вручную

Результат — референс раскладки для разработки, а не спека, которую копируют
пиксель в пиксель.
